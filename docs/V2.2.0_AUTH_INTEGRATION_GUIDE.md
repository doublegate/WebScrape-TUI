# v2.2.0 Enhanced Authentication Integration Guide

This document provides step-by-step instructions for integrating the v2.2.0 security enhancements into the main `scrapetui.py` application.

## Overview

The v2.2.0 security features are implemented in separate modules:
- `scrapetui/core/password_policy.py` - Password validation and strength checking
- `scrapetui/core/rate_limit.py` - Login rate limiting and account lockout
- `scrapetui/core/audit.py` - Security audit logging
- `scrapetui/core/password_reset.py` - Password reset token management
- `scrapetui/core/quotas.py` - User resource quotas
- `scrapetui/core/auth_enhanced.py` - Integration of all security features

These need to be integrated into the main TUI application.

```python
def on_button_pressed(self, event: Button.Pressed) -> None:
    """Handle button clicks with enhanced password policy."""
    if event.button.id == "change-btn":
        current = self.query_one("#current-pwd", Input).value
        new = self.query_one("#new-pwd", Input).value
        confirm = self.query_one("#confirm-pwd", Input).value

        # Validation
        if not all([current, new, confirm]):
            self.app.notify("All fields are required", severity="error")
            return

        if new != confirm:
            self.app.notify("New passwords do not match", severity="error")
            return

        # Use enhanced password change with policy validation
        success, message = change_password_with_policy(
            self.user_id,
            current,
            new
        )

        if success:
            self.app.notify(message, severity="information")
            self.dismiss(True)
        else:
            self.app.notify(message, severity="error")
    else:
        self.dismiss(False)
```

### 6. Add Security Action Methods

Add these methods to the `WebScraperApp` class:

```python
def action_view_security_status(self) -> None:
    """Show account security status (Ctrl+Shift+S)."""
    if self.current_user_id is None:
        self.notify("Not logged in", severity="warning")
        return

    self.push_screen(
        AccountSecurityModal(
            self.current_user_id,
            self.current_username
        )
    )


def action_view_audit_log(self) -> None:
    """View audit log - admin only (Ctrl+Shift+A)."""
    if not self._check_admin_permission():
        return

    self.push_screen(AuditLogViewerModal(self.current_user_id))


def action_manage_quotas(self) -> None:
    """Manage user quotas - admin only (Ctrl+Shift+Q)."""
    if not self._check_admin_permission():
        return

    self.push_screen(
        QuotaManagementModal(
            self.current_user_id,
            target_user_id=None  # Will prompt for username
        )
    )


def action_password_reset_token(self) -> None:
    """Generate password reset token - admin only (Ctrl+Shift+R)."""
    if not self._check_admin_permission():
        return

    self.push_screen(PasswordResetRequestModal(self.current_user_id))


def _check_admin_permission(self) -> bool:
    """Check if current user is admin."""
    if self.current_user_role != "admin":
        self.notify(
            "This feature requires administrator privileges",
            severity="error"
        )
        return False
    return True
```

## Configuration

Default password policy can be customized by creating a `PasswordPolicy` instance:

```python
# Custom policy for development/testing
dev_policy = PasswordPolicy(
    min_length=8,
    require_special=False
)

# Pass to user creation
user_id, msg = create_user_with_policy(
    username,
    password,
    password_policy=dev_policy
)
```

Default quotas can be adjusted in the database:

```sql
-- Set custom default quotas
UPDATE users SET article_quota = 20000, scraper_quota = 200 WHERE role = 'user';

-- Set unlimited for power users
UPDATE users SET article_quota = -1, scraper_quota = -1 WHERE username = 'poweruser';
```

## Additional Notes

1. **IP Address Tracking:** The current integration uses a placeholder IP address (`127.0.0.1`). For production, consider adding actual IP detection.

2. **User Agent:** Currently set to `"WebScrape-TUI"`. Could be enhanced with version information.

3. **Email Notifications:** Password reset tokens are currently displayed in the TUI. For production, implement email sending.

4. **Rate Limit Configuration:** Default is 5 attempts with 15-minute lockout. Can be customized via `RateLimitConfig`.

5. **Audit Log Retention:** Default retention is 90 days. Periodically run cleanup:
   ```bash
   scrapetui-cli security audit cleanup --days 90 --confirm
   ```

## Performance Considerations

The security features add minimal overhead:
- Password hashing: ~100ms per login (bcrypt cost factor 12)
- Audit logging: <1ms per event (async recommended for production)
- Quota checking: <1ms (indexed database query)
- Rate limit checking: <5ms (includes failed attempt counting)

For high-traffic scenarios, consider:
- Implementing connection pooling
- Using async database operations
- Caching user roles and permissions
- Implementing token-based session management
