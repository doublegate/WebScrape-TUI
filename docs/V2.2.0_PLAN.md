**Version**: v2.2.0 (Security & Administration Enhancements)
**Planned Start**: 2025-11-18

## Executive Summary

v2.2.0 focuses on enhancing security, administrative capabilities, and user management features. This release builds on the solid v2.1.0 foundation to make the application more secure, auditable, and easier to administer in multi-user environments.

### Release Goals

1. **Enhanced Security**: Password policies, rate limiting, account lockout
2. **Better User Management**: Password reset, account recovery
3. **Administrative Tools**: Audit logging, user quotas
4. **Production Hardening**: Security best practices for enterprise use

---

## Feature Prioritization

### Phase 1: Security Enhancements (HIGH PRIORITY)
**Estimated Effort**: 4-6 hours

1. **Password Complexity Requirements**
   - Minimum length (configurable, default: 12 characters)
   - Character requirements (uppercase, lowercase, numbers, special chars)
   - Password strength meter
   - Common password blacklist
   - **Files**: `scrapetui/core/auth.py`, `scrapetui/core/password_policy.py`
   - **Tests**: `tests/unit/test_password_policy.py`

2. **Login Rate Limiting & Account Lockout**
   - Track failed login attempts per user
   - Configurable lockout threshold (default: 5 attempts)
   - Configurable lockout duration (default: 15 minutes)
   - Auto-unlock after duration
   - Admin can manually unlock accounts
   - **Files**: `scrapetui/core/auth.py`, new table `login_attempts`
   - **Tests**: `tests/unit/test_rate_limiting.py`

3. **Session Security Enhancements**
   - Force password change on first login
   - Track last password change date
   - Password expiration (configurable, default: 90 days)
   - Session invalidation on password change
   - **Files**: `scrapetui/core/auth.py`, update `users` table
   - **Tests**: `tests/unit/test_session_security.py`

### Phase 2: User Management (HIGH PRIORITY)
**Estimated Effort**: 3-4 hours

4. **Password Reset Functionality**
   - Token-based password reset (no email required)
   - Admin-initiated password reset
   - Reset tokens with expiration (default: 24 hours)
   - One-time use tokens
   - **Files**: `scrapetui/core/auth.py`, new table `password_reset_tokens`
   - **Tests**: `tests/unit/test_password_reset.py`
   - **UI**: New modal for password reset in TUI

5. **Account Recovery**
   - Admin can reset user passwords
   - Admin can unlock user accounts
   - Password reset via CLI command
   - **Files**: `scrapetui/cli/commands/user.py`
   - **Tests**: `tests/cli/test_user_commands.py`

### Phase 3: Administrative Features (MEDIUM PRIORITY)
**Estimated Effort**: 3-4 hours

6. **Audit Logging System**
   - Log all security-relevant events
   - Events: login, logout, failed login, password change, user creation, etc.
   - Structured logging with JSON format
   - Retention policy (default: 90 days)
   - Admin audit log viewer (TUI and CLI)
   - **Files**: `scrapetui/core/audit.py`, new table `audit_log`
   - **Tests**: `tests/unit/test_audit.py`

7. **User Quotas (Basic)**
   - Article count quota per user (default: 10,000)
   - Scraper profile quota per user (default: 100)
   - Configurable quotas per user or role
   - Quota enforcement on create operations
   - Quota display in user profile
   - **Files**: `scrapetui/core/quotas.py`, update `users` table
   - **Tests**: `tests/unit/test_quotas.py`

### Phase 4: Optional Enhancements (LOW PRIORITY)
**Estimated Effort**: 2-3 hours (if time permits)

8. **Enhanced Monitoring**
   - System health dashboard
   - Active sessions viewer
   - User activity metrics
   - Database size monitoring
   - **Files**: `scrapetui/ui/modals/system_health.py`

9. **Security Headers & Best Practices**
   - API security headers
   - CORS configuration
   - Rate limiting for API endpoints
   - **Files**: `scrapetui/api/middleware.py`

## Database Schema Changes

### New Tables

```sql
-- Login attempts tracking for rate limiting
CREATE TABLE IF NOT EXISTS login_attempts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL,
    ip_address TEXT,
    success INTEGER NOT NULL DEFAULT 0,
    attempted_at TEXT NOT NULL,
    INDEX idx_username_attempted (username, attempted_at)
);

-- Password reset tokens
CREATE TABLE IF NOT EXISTS password_reset_tokens (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    token TEXT NOT NULL UNIQUE,
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL,
    used_at TEXT,
    created_by INTEGER,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
);

-- Audit log for security events
CREATE TABLE IF NOT EXISTS audit_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER,
    username TEXT,
    event_type TEXT NOT NULL,
    event_data TEXT,
    ip_address TEXT,
    user_agent TEXT,
    created_at TEXT NOT NULL,
    INDEX idx_user_created (user_id, created_at),
    INDEX idx_event_created (event_type, created_at),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

### Modified Tables

```sql
-- Add to users table
ALTER TABLE users ADD COLUMN account_locked INTEGER NOT NULL DEFAULT 0;
ALTER TABLE users ADD COLUMN locked_until TEXT;
ALTER TABLE users ADD COLUMN failed_login_attempts INTEGER NOT NULL DEFAULT 0;
ALTER TABLE users ADD COLUMN last_failed_login TEXT;
ALTER TABLE users ADD COLUMN password_changed_at TEXT;
ALTER TABLE users ADD COLUMN force_password_change INTEGER NOT NULL DEFAULT 0;
ALTER TABLE users ADD COLUMN article_quota INTEGER NOT NULL DEFAULT 10000;
ALTER TABLE users ADD COLUMN scraper_quota INTEGER NOT NULL DEFAULT 100;
```

## CLI Commands

### New Commands

```bash
# Password reset
scrapetui-cli user reset-password <username> --generate-token

# Audit log
scrapetui-cli admin audit --user <username> --event-type <type> --since <date>
```

## Migration Path

### From v2.1.0 to v2.2.0

**Automatic Migration**:
1. Detect v2.1.0 schema (version 2.0.1)
2. Add new tables (login_attempts, password_reset_tokens, audit_log)
3. Add new columns to users table
4. Set default values for existing users
5. Update schema version to 2.2.0
6. Create initial audit log entry for migration

**Backward Compatibility**:
- All v2.1.0 features remain functional
- Existing users not affected by new password policy (grandfathered)
- Optional: Admin can force password change for all users
- No breaking API changes

**Migration Script**: `scrapetui/database/migrations/v2.2.0.py`
