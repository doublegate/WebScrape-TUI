## 📚 Documentation Best Practices

### When to Update

- **After major features** - Update PROJECT-STATUS.md, ROADMAP.md
- **After releases** - Update CHANGELOG.md, README.md, version files
- **After planning** - Create planning documents (like v2.3.0)
- **Weekly** - Review TECHNICAL_DEBT.md, update issues
- **Monthly** - Review all docs for accuracy

### Documentation Standards

1. **Keep it Current** - Update docs immediately after changes
2. **Be Consistent** - Follow established formats and styles
3. **Be Comprehensive** - Include examples, use cases, and edge cases
4. **Be Concise** - Remove outdated information
5. **Use Links** - Cross-reference related documents

### File Naming Conventions

- **Core docs**: UPPERCASE.md (README.md, CHANGELOG.md)
- **Feature guides**: Title_Case.md (API.md, CLI.md)
- **Version docs**: V{version}_TITLE.md (V2.3.0_FEATURE_PLAN.md)
- **Session docs**: SESSION_SUMMARY_{topic}.md

## 🗂️ Archival Policy

### When to Archive

Documents should be moved to `docs/archive/` when:
- Superseded by newer documentation
- Historical value only (session summaries)
- Specific to completed milestones
- No longer actively referenced

### Archive Directory Structure

```
docs/archive/
├── sessions/           # Session summaries
│   ├── 2025-10-05_v2.1.0_release.md
```
